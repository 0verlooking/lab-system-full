# Технічне Завдання - Система Управління Лабораторіями

## 1. Загальні відомості

### 1.1 Назва системи
Система Управління Лабораторіями (Lab Management System)

### 1.2 Призначення системи
Веб-система для автоматизації процесів управління лабораторіями навчального закладу, включаючи:
- Управління лабораторіями та обладнанням
- Резервація лабораторних ресурсів
- Репозиторій навчальних проектів
- Керування складом комплектуючих
- Документообіг та звітність

### 1.3 Замовник
Навчальний заклад (університет/коледж)

### 1.4 Підстава для розробки
Курсова робота з дисципліни "Проектування Програмного Забезпечення"

## 2. Цілі та завдання

### 2.1 Цілі розробки
- Автоматизація процесів управління лабораторіями
- Спрощення резервації обладнання для студентів
- Створення централізованого репозиторію навчальних проектів
- Покращення контролю за використанням обладнання
- Оптимізація документообігу

### 2.2 Основні завдання
1. Розробити веб-додаток для управління лабораторіями
2. Реалізувати систему аутентифікації та авторизації
3. Створити функціонал резервації обладнання
4. Розробити репозиторій проектів
5. Реалізувати систему документообігу
6. Забезпечити безпеку даних
7. Створити зручний інтерфейс користувача

## 3. Функціональні вимоги

### 3.1 Аутентифікація та авторизація

#### 3.1.1 Реєстрація користувачів
- **Вхідні дані:** username, password, role
- **Валідація:**
  - username: унікальний, 3-50 символів
  - password: мінімум 8 символів
  - role: ADMIN або STUDENT
- **Вихідні дані:** JWT токен, роль користувача
- **Помилки:**
  - 400: Невалідні дані
  - 409: Користувач вже існує

#### 3.1.2 Вхід у систему
- **Вхідні дані:** username, password
- **Обробка:**
  - Перевірка наявності користувача
  - Верифікація пароля (BCrypt)
  - Генерація JWT токену
- **Вихідні дані:** JWT токен (термін дії: 1 година), роль
- **Помилки:**
  - 401: Невірні облікові дані

### 3.2 Управління лабораторіями

#### 3.2.1 Створення лабораторії (ADMIN)
- **Вхідні дані:**
  - name: назва лабораторії
  - location: розташування
  - capacity: місткість (кількість місць)
  - description: опис
- **Валідація:**
  - name: обов'язкове, 1-255 символів
  - capacity: додатнє число
- **Вихідні дані:** Об'єкт створеної лабораторії
- **Помилки:**
  - 400: Невалідні дані
  - 403: Доступ заборонено

#### 3.2.2 Редагування лабораторії (ADMIN)
- Аналогічно до створення
- Додатково: перевірка існування за ID

#### 3.2.3 Видалення лабораторії (ADMIN)
- **Вхідні дані:** lab_id
- **Обробка:** Каскадне видалення резервацій
- **Помилки:**
  - 404: Лабораторія не знайдена
  - 403: Доступ заборонено

#### 3.2.4 Перегляд списку лабораторій (ALL)
- **Вихідні дані:** Список всіх лабораторій
- **Фільтрація:** За назвою, розташуванням

### 3.3 Управління обладнанням

#### 3.3.1 Додавання обладнання (ADMIN)
- **Вхідні дані:**
  - name: назва обладнання
  - inventoryNumber: інвентарний номер (унікальний)
  - status: AVAILABLE/MAINTENANCE/BROKEN
  - labId: ID лабораторії
  - documentationLink: посилання на документацію (опційно)
  - description: опис (опційно)
- **Валідація:**
  - inventoryNumber: унікальний
  - status: допустимі значення enum
- **Вихідні дані:** Об'єкт створеного обладнання
- **Помилки:**
  - 400: Невалідні дані
  - 409: Інвентарний номер вже існує

#### 3.3.2 Оновлення статусу обладнання (ADMIN)
- **Вхідні дані:** equipment_id, new_status
- **Валідація:** Допустимі значення статусу
- **Автоматичне:** updated_at = current timestamp

#### 3.3.3 Перегляд обладнання лабораторії (ALL)
- **Вхідні дані:** lab_id
- **Вихідні дані:** Список обладнання з статусами
- **Фільтрація:** За статусом, назвою

### 3.4 Резервація ресурсів

#### 3.4.1 Створення резервації (STUDENT)
- **Вхідні дані:**
  - labId: ID лабораторії
  - startTime: час початку
  - endTime: час закінчення
  - purpose: мета резервації
  - equipmentIds: список ID обладнання (опційно)
- **Валідація:**
  - Часові перевірки (Strategy Pattern):
    - startTime < endTime
    - startTime >= поточний час
    - Тривалість: 1-8 годин
  - Перевірка доступності лабораторії
  - Перевірка доступності обладнання
- **Обробка:**
  - Статус: PENDING
  - Збереження в БД
  - Публікація події (Observer Pattern)
  - Сповіщення адміністратора
- **Вихідні дані:** Об'єкт резервації
- **Помилки:**
  - 400: Невалідні дані
  - 409: Конфлікт резервацій

#### 3.4.2 Погодження резервації (ADMIN)
- **Вхідні дані:** reservation_id, status (APPROVED/REJECTED)
- **Обробка:**
  - Оновлення статусу
  - approvedBy = current user
  - approvedAt = current timestamp
  - Публікація події
  - Сповіщення студента
- **Вихідні дані:** Оновлений об'єкт резервації

#### 3.4.3 Перегляд власних резервацій (STUDENT)
- **Фільтрація:** За userId поточного користувача
- **Сортування:** За датою створення (desc)

#### 3.4.4 Перегляд всіх резервацій (ADMIN)
- **Фільтрація:** За статусом, лабораторією, користувачем
- **Пагінація:** (майбутня функція)

### 3.5 Лабораторні роботи (Проекти)

#### 3.5.1 Створення проекту (STUDENT)
- **Вхідні дані:**
  - title: назва проекту
  - description: опис
  - requiredEquipmentIds: список необхідного обладнання
- **Обробка:**
  - authorId = current user
  - status = DRAFT
  - Збереження в БД
- **Вихідні дані:** Об'єкт проекту

#### 3.5.2 Публікація проекту (STUDENT)
- **Вхідні дані:** project_id
- **Обробка:**
  - Перевірка повноти даних
  - status = PUBLISHED
- **Ефект:** Проект стає доступним іншим користувачам

#### 3.5.3 Перегляд проектів (ALL)
- **Фільтрація:** За статусом (PUBLISHED для STUDENT)
- **Пошук:** За назвою, описом

## 5. Архітектура системи

### 5.1 Загальна архітектура
```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│   Frontend   │─────▶│   Backend    │─────▶│  PostgreSQL  │
│  React + TS  │ HTTP │ Spring Boot  │ JDBC │   Database   │
└──────────────┘      └──────────────┘      └──────────────┘
```

### 5.2 Backend Architecture (Layered)
```
Controller Layer    → REST API endpoints
    ↓
Service Layer       → Business logic + Patterns
    ↓
Repository Layer    → Data access (Spring Data JPA)
    ↓
Domain Layer        → Entity classes
```

### 5.3 Патерни проектування

#### 5.3.1 Factory Pattern
- **Застосування:** NotificationFactory
- **Мета:** Створення різних типів повідомлень (Email, SMS)
- **Переваги:** Легке додавання нових типів

#### 5.3.2 Strategy Pattern
- **Застосування:** ReservationValidationStrategy
- **Стратегії:**
  - TimeSlotValidationStrategy
  - DurationValidationStrategy
- **Мета:** Гнучка валідація резервацій

#### 5.3.3 Observer Pattern
- **Застосування:** Spring Events для резервацій
- **Події:** CREATED, APPROVED, REJECTED, CANCELLED
- **Listener:** NotificationListener
- **Мета:** Сповіщення користувачів

#### 5.3.4 Builder Pattern
- **Застосування:** Domain entities (через Lombok @Builder)
- **Мета:** Зручне створення складних об'єктів

### 5.4 SOLID Принципи

#### S - Single Responsibility Principle
- Кожен Service відповідає за один домен
- Окремі класи для різних типів валідації

#### O - Open/Closed Principle
- Легке додавання нових стратегій валідації
- Розширення функціоналу без зміни існуючого коду

#### L - Liskov Substitution Principle
- Всі реалізації інтерфейсів взаємозамінні

#### I - Interface Segregation Principle
- Вузькі інтерфейси (Notification, ValidationStrategy)

#### D - Dependency Inversion Principle
- Залежність від абстракцій (Repository interfaces)
- Constructor injection через @RequiredArgsConstructor

## 8. API Endpoints

### 8.1 Authentication
- `POST /api/auth/register` - Реєстрація
- `POST /api/auth/login` - Вхід

### 8.2 Labs
- `GET /api/labs` - Список лабораторій
- `POST /api/labs` - Створення (ADMIN)
- `PUT /api/labs/{id}` - Оновлення (ADMIN)
- `DELETE /api/labs/{id}` - Видалення (ADMIN)

### 8.3 Equipment
- `GET /api/equipment/lab/{labId}` - Обладнання лабораторії
- `POST /api/equipment` - Додавання (ADMIN)
- `PUT /api/equipment/{id}` - Оновлення (ADMIN)
- `DELETE /api/equipment/{id}` - Видалення (ADMIN)

### 8.4 Reservations
- `POST /api/reservations` - Створення резервації
- `GET /api/reservations/my` - Мої резервації
- `GET /api/reservations` - Всі резервації (ADMIN)
- `PUT /api/reservations/{id}/status` - Зміна статусу (ADMIN)

### 8.5 Lab Works
- `POST /api/labworks` - Створення проекту
- `GET /api/labworks` - Список проектів
- `GET /api/labworks/{id}` - Деталі проекту
- `PUT /api/labworks/{id}` - Оновлення проекту

Детальну документацію API дивіться в [README.md](../README.md)
