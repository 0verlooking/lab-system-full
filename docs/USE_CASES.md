# Use Case Діаграми

## Огляд системи

Система управління лабораторіями має три основні типи користувачів:
- **Студент** - може резервувати лабораторії, переглядати обладнання
- **Викладач/Лаборант** - може управляти резерваціями, лабораторіями
- **Адміністратор** - має повний доступ до системи

## Use Case 1: Аутентифікація

### Актори
- Користувач (всі ролі)

### Опис
Користувач входить у систему за допомогою логіну та пароля.

### Передумови
- Користувач має створений обліковий запис

### Основний сценарій
1. Користувач відкриває сторінку входу
2. Вводить логін та пароль
3. Система перевіряє облікові дані
4. Система генерує JWT токен
5. Користувач перенаправляється на головну сторінку

### Альтернативні сценарії
- **1a.** Неправильні облікові дані
  - Система показує повідомлення про помилку
  - Користувач може спробувати знову

### Постумови
- Користувач увійшов у систему
- JWT токен збережено в localStorage

```
┌─────────────────┐
│   Користувач    │
└────────┬────────┘
         │
         │ <<include>>
         ▼
    ┌────────┐
    │ Логін  │
    └────────┘
         │
         ├──────> Введення логіну/паролю
         │
         ├──────> Перевірка облікових даних
         │
         └──────> Отримання JWT токену
```

## Use Case 2: Управління лабораторіями (Адміністратор)

### Актори
- Адміністратор

### Опис
Адміністратор може створювати, редагувати та видаляти лабораторії.

### Передумови
- Користувач увійшов як адміністратор

### Основний сценарій (Створення лабораторії)
1. Адміністратор відкриває список лабораторій
2. Натискає кнопку "Додати лабораторію"
3. Заповнює форму:
   - Назва лабораторії
   - Локація
   - Місткість
   - Опис
4. Натискає "Зберегти"
5. Система створює нову лабораторію
6. Лабораторія додається до списку

### Альтернативні сценарії
- **3a.** Невалідні дані
  - Система показує повідомлення про помилку валідації
  - Адміністратор виправляє дані

### Постумови
- Нова лабораторія створена та доступна в системі

```
┌──────────────────┐
│  Адміністратор   │
└────────┬─────────┘
         │
         ├──────> Створити лабораторію
         │
         ├──────> Редагувати лабораторію
         │
         └──────> Видалити лабораторію
```

## Use Case 3: Резервація лабораторії (Студент)

### Актори
- Студент

### Опис
Студент може резервувати лабораторію на певний час.

### Передумови
- Студент увійшов у систему
- Існує доступна лабораторія

### Основний сценарій
1. Студент відкриває список лабораторій
2. Вибирає лабораторію
3. Натискає "Зарезервувати"
4. Заповнює форму резервації:
   - Дата початку
   - Дата закінчення
   - Мета використання
5. Натискає "Відправити запит"
6. Система створює резервацію зі статусом "PENDING"
7. Система сповіщає адміністратора про новий запит

### Альтернативні сценарії
- **4a.** Лабораторія вже зарезервована на цей час
  - Система показує повідомлення про конфлікт
  - Студент вибирає інший час

- **4b.** Невалідний часовий проміжок
  - Система показує повідомлення про помилку
  - Студент виправляє дані

### Постумови
- Резервація створена зі статусом "PENDING"
- Адміністратор отримує сповіщення

```
┌─────────────┐
│   Студент   │
└──────┬──────┘
       │
       ├──────> Переглянути лабораторії
       │
       ├──────> Створити резервацію
       │         │
       │         ├──> Вибрати лабораторію
       │         ├──> Вказати час
       │         └──> Вказати мету
       │
       └──────> Переглянути мої резервації
```

## Use Case 4: Управління обладнанням (Адміністратор/Лаборант)

### Актори
- Адміністратор
- Лаборант

### Опис
Адміністратор або лаборант може додавати, редагувати та видаляти обладнання.

### Передумови
- Користувач увійшов як адміністратор або лаборант
- Існує лабораторія

### Основний сценарій (Додавання обладнання)
1. Користувач відкриває лабораторію
2. Натискає "Додати обладнання"
3. Заповнює форму:
   - Назва обладнання
   - Інвентарний номер
   - Статус (AVAILABLE, MAINTENANCE, BROKEN)
4. Натискає "Зберегти"
5. Система додає обладнання до лабораторії
6. Обладнання відображається в списку

### Альтернативні сценарії
- **3a.** Інвентарний номер вже існує
  - Система показує повідомлення про дублікат
  - Користувач вводить інший номер

### Постумови
- Обладнання додано до лабораторії
- Обладнання доступне для перегляду

```
┌──────────────────────┐
│ Адміністратор/       │
│ Лаборант             │
└──────────┬───────────┘
           │
           ├──────> Додати обладнання
           │
           ├──────> Редагувати обладнання
           │
           ├──────> Змінити статус обладнання
           │
           └──────> Видалити обладнання
```

## Use Case 5: Погодження резервації (Адміністратор)

### Актори
- Адміністратор

### Опис
Адміністратор переглядає запити на резервацію та погоджує або відхиляє їх.

### Передумови
- Адміністратор увійшов у систему
- Існує резервація зі статусом "PENDING"

### Основний сценарій (Погодження)
1. Адміністратор відкриває список резервацій
2. Фільтрує за статусом "PENDING"
3. Вибирає резервацію для перегляду
4. Переглядає деталі:
   - Студент, що запитує
   - Лабораторія
   - Час
   - Мета
5. Натискає "Погодити"
6. Система змінює статус на "APPROVED"
7. Студент отримує сповіщення про погодження

### Альтернативні сценарії
- **5a.** Відхилення резервації
  - Адміністратор натискає "Відхилити"
  - Вводить причину відхилення (опціонально)
  - Система змінює статус на "REJECTED"
  - Студент отримує сповіщення про відхилення

### Постумови
- Статус резервації змінено
- Студент отримав сповіщення

```
┌──────────────────┐
│  Адміністратор   │
└────────┬─────────┘
         │
         ├──────> Переглянути запити
         │
         ├──────> Погодити резервацію
         │
         └──────> Відхилити резервацію
                   │
                   └──> Вказати причину
```

## Use Case 6: Перегляд обладнання (Студент)

### Актори
- Студент

### Опис
Студент може переглядати доступне обладнання в лабораторіях.

### Передумови
- Студент увійшов у систему

### Основний сценарій
1. Студент відкриває список лабораторій
2. Вибирає лабораторію
3. Система показує список обладнання з:
   - Назвою
   - Інвентарним номером
   - Статусом
4. Студент переглядає інформацію

### Постумови
- Студент отримав інформацію про обладнання

```
┌─────────────┐
│   Студент   │
└──────┬──────┘
       │
       ├──────> Переглянути лабораторії
       │
       └──────> Переглянути обладнання
                 │
                 ├──> Фільтрувати за статусом
                 └──> Пошук за назвою
```

## Висновки

Система забезпечує повний цикл управління лабораторіями:
1. **Аутентифікація** - безпечний вхід з JWT токенами
2. **Управління лабораторіями** - створення та редагування
3. **Управління обладнанням** - відстеження статусу
4. **Резервація** - запити та погодження
5. **Перегляд інформації** - доступ до даних

Кожен use case реалізований з урахуванням різних сценаріїв та обробкою помилок.
